# Логічні Годинники у Розподілених Системах

## Огляд

Цей проект реалізує два типи логічних годинників для встановлення причинно-наслідкового упорядкування подій у розподілених системах:

1. **Логічний Годинник Лемпорта (Lamport Clock)** - забезпечує повне упорядкування подій
2. **Векторний Годинник (Vector Clock / Terr's Algorithm)** - забезпечує часткове упорядкування та дозволяє виявити причинно-наслідкові зв'язки

## Логічний Годинник Лемпорта

### Концепція

Логічний годинник Лемпорта - це простий лічильник, який інкрементується на кожну подію:

- **Внутрішня подія**: `L = L + 1`
- **Відправка повідомлення**: `L = L + 1`, потім надсилаємо `L`
- **Отримання повідомлення**: `L = max(L, received_timestamp) + 1`

### Переваги

- ✓ Простий та легкий у реалізації
- ✓ Мінімальні накладні витрати (одне число на процес)
- ✓ Забезпечує повне упорядкування подій

### Недоліки

- ✗ Не розрізняє причинно-наслідкові та одночасні события
- ✗ Два процеси можуть мати однакові мітки часу для різних подій

### Приклад використання

```python
from scheduler.clocks.lamport_clock import LamportClock

# Ініціалізація
clock1 = LamportClock(0)
clock2 = LamportClock(0)

# Внутрішня подія
clock1.increment_internal()  # clock1 = 1

# Відправка повідомлення
ts = clock1.send_timestamp()  # clock1 = 2, ts = 2

# Отримання
clock2.receive_timestamp(ts)  # clock2 = max(0, 2) + 1 = 3
```

## Векторний Годинник (Алгоритм Террі)

### Концепція

Векторний годинник - це вектор лічильників, по одному на кожен процес.

Кожен процес `i` зберігає вектор `V[0..n-1]`, де:
- `V[i]` = кількість подій у процесі `i`
- `V[j]` (j ≠ i) = знання процесу `i` про подій у процесі `j`

### Правила оновлення

1. **Внутрішня подія на процесі `i`**:
   ```
   V[i] = V[i] + 1
   ```

2. **Відправка повідомлення на процесі `i`**:
   ```
   V[i] = V[i] + 1
   надсилаємо V
   ```

3. **Отримання повідомлення на процесі `i`** від іншого процесу:
   ```
   для кожного j: V[j] = max(V[j], received_V[j])
   V[i] = V[i] + 1
   ```

### Визначення причинно-наслідкових зв'язків

Дві мітки часу `A` та `B` порівнюються:

- **A happened-before B**: `A[i] ≤ B[i]` для всіх `i`, та `A ≠ B`
- **Concurrent**: ні A happened-before B, ні B happened-before A

### Переваги

- ✓ Розрізняє причинно-наслідкові та одночасні события
- ✓ Дозволяє визначити причинно-наслідкову залежність між подіями
- ✓ Повна інформація про знання кожного процесу

### Недоліки

- ✗ Накладні витрати зростають з кількістю процесів (O(n))
- ✗ Більш складна реалізація та аналіз

### Приклад використання

```python
from scheduler.clocks.vector_clock import VectorClock

# Ініціалізація для 3 процесів
vc0 = VectorClock(0, 3)  # Процес 0
vc1 = VectorClock(1, 3)  # Процес 1
vc2 = VectorClock(2, 3)  # Процес 2

# Процес 0 відправляє до Процесу 1
ts = vc0.send_timestamp()  # [1, 0, 0]
vc1.receive_timestamp(ts)   # [1, 1, 0]

# Процес 1 відправляє до Процесу 2
ts = vc1.send_timestamp()  # [1, 2, 0]
vc2.receive_timestamp(ts)   # [1, 2, 1]

# Перевірка причинно-наслідкових зв'язків
print(vc0.happened_before(vc1.get_timestamp()))  # True
print(vc1.happened_before(vc2.get_timestamp()))  # True
```

## Вузли та Мережа

### NodeWithClocks

Розширений вузол із підтримкою логічних годинників:

```python
from scheduler.implementation.node_with_clocks import NodeWithClocks

node = NodeWithClocks(
    node_id=node_uuid,
    neighbors=[neighbor1_uuid, neighbor2_uuid],
    process_index=0,
    num_processes=4,
    enable_lamport=True,
    enable_vector=True
)

# Відправка повідомлення
msg = node.send_message_to(neighbor_id, "message_data")

# Обробка отриманого повідомлення
response = node.process_action(received_message)

# Отримання поточних значень годинників
clock_info = node.get_clock_info()
# {'lamport': 5, 'vector': [1, 3, 2, 0]}
```

### NetworkWithClocks

Мережа вузлів із логічними годинниками:

```python
from scheduler.implementation.network_with_clocks import NetworkWithClocks

# Створення мережи з 4 вузлами
network = NetworkWithClocks(
    num_nodes=4,
    enable_lamport=True,
    enable_vector=True
)

# Доступ до вузлів
node0 = network.clock_nodes[0]

# Вивід поточних значень годинників
network.print_clocks()

# Вивід історії подій
network.print_events()
```

## Теоретичні основи

### Причинно-наслідкові зв'язки

У розподілених системах нас цікавлять такі відносини між подіями:

1. **Happens-Before** (⟶): Подія A сталася раніше за подію B
   - Якщо A та B в одному процесі, і A передує B
   - Якщо A - це відправка повідомлення, а B - його отримання

2. **Concurrent**: Жодна з подій не сталася раніше за іншу

### Властивості Vector Clocks

- **Правильність**: Якщо A ⟶ B, то VC(A) < VC(B)
- **Повнота**: Якщо VC(A) < VC(B), то A ⟶ B
- **Одночасність**: Якщо A || B, то VC(A) і VC(B) не порівняні

## Застосування

Логічні годинники використовуються для:

1. **Встановлення каузального упорядкування**: Визначення, який порядок подій був насправді
2. **Розпізнання конфліктів**: Виявлення одночасних операцій, які можуть конфліктувати
3. **Отримання знімків стану**: Визначення глобально узгодженого стану системи
4. **Синхронізація**: Координування роботи процесів
5. **Кеш-когерентність**: Забезпечення узгодженості розподіленого кешу

## Висновки

Логічні годинники - це фундаментальний інструмент розподілених систем, який дозволяє встановити причинно-наслідкове упорядкування без синхронних фізичних годинників.

- **Lamport Clock** прості та ефективні для встановлення повного упорядкування
- **Vector Clocks** надають більш детальну інформацію про причинно-наслідкові зв'язки

Вибір залежить від вимог конкретної системи та компромісу між складністю та точністю.
