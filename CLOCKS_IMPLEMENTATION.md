## Реалізація Логічних Годинників у Алгоритмі Террі

### Огляд

Цей проект реалізує два типи логічних годинників для розподіленої системи, базуючись на алгоритмі хвилі Террі (Tarry):

1. **Логічний годинник Лемпорта** (Lamport Logical Clock)
2. **Векторний годинник** (Vector Clock)

### Структура Реалізації

#### 1. Логічний Годинник Лемпорта (`scheduler/core/lamport_clock.py`)

Логічний годинник Лемпорта - це проста лічильна система для впорядкування подій у розподіленій системі.

**Основні правила:**
- Кожен вузол має локальний лічильник часу
- При кожній локальній дії лічильник збільшується на 1
- При отриманні повідомлення: `new_clock = max(local_clock, received_clock) + 1`

**Ключові методи:**
- `increment()` - збільшити часовику мітку при локальній дії
- `update_on_receive(received_timestamp)` - оновити часовику мітку при отриманні повідомлення
- `get_timestamp()` - отримати поточну часову мітку

**Приклад використання:**
```python
lamport_clock = LamportClock(node_id)
lamport_clock.increment()  # Повертає 1
received_timestamp = 5
lamport_clock.update_on_receive(received_timestamp)  # Повертає 6
```

#### 2. Векторний Годинник (`scheduler/core/vector_clock.py`)

Векторний годинник розширює концепцію логічного годинника, зберігаючи часову мітку для кожного вузла у системі.

**Основні правила:**
- Кожен вузол i має вектор розміру n (кількість вузлів)
- `vector[i]` - локальний часовик цього вузла
- `vector[j]` (j ≠ i) - остання відома часова мітка вузла j
- При локальній дії: `vector[i] += 1`
- При отриманні повідомлення:
  - Для j ≠ i: `vector[j] = max(local[j], received[j])`
  - Потім: `vector[i] += 1`

**Ключові методи:**
- `increment()` - збільшити локальний елемент вектора
- `update_on_receive(received_vector)` - оновити вектор при отриманні повідомлення
- `get_vector()` - отримати поточний вектор

**Приклад використання:**
```python
vector_clock = VectorClock(node_id, [node1_id, node2_id, node3_id])
vector_clock.increment()  # Збільшує елемент цього вузла
received_vector = {...}
vector_clock.update_on_receive(received_vector)  # Оновлює весь вектор
```

#### 3. Інтеграція з TarryNode (`scheduler/implementation/tarry_node.py`)

Клас `TarryNode` розширений для використання обох типів годинників:

**В конструкторі:**
```python
def __init__(self, node_id, neighbors, all_node_ids=None):
    ...
    self.lamport_clock = LamportClock(node_id)
    self.vector_clock = VectorClock(node_id, all_node_ids)
```

**При обробці повідомлення:**
```python
def process_action(self, message: Action) -> NodeResponse:
    # Оновити обидва годинники при отриманні повідомлення
    if message.data.get('lamport_timestamp') is not None:
        received_lamport = message.data.get('lamport_timestamp')
        self.lamport_clock.update_on_receive(received_lamport)
    
    if message.data.get('vector_timestamp') is not None:
        received_vector = message.data.get('vector_timestamp')
        self.vector_clock.update_on_receive(received_vector)
    ...
```

**При відправленні повідомлення:**
```python
def start_wave(self, message: dict[str, Any]) -> Dict[uuid.UUID, List[Any]]:
    # Збільшити обидва годинники
    self.lamport_clock.increment()
    self.vector_clock.increment()
    
    offer = {
        'sender_id': self.node_id,
        'transaction_data': transaction_data,
        'message_type': "Offer",
        'lamport_timestamp': self.lamport_clock.get_timestamp(),
        'vector_timestamp': self.vector_clock.get_vector()
    }
    ...
```

### Алгоритм Террі (Tarry Algorithm)

Алгоритм Террі знаходить остовне дерево у розподіленій системі та зібрває інформацію від усіх вузлів.

**Основна ідея:**
1. Вузол, який отримав повідомлення вперше, стає дитиною відправника
2. Вузол відправляє повідомлення всім сусідам, крім батька
3. Коли немає більше сусідів для відправлення, вузол відправляє повідомлення батькові
4. Коли батько отримує повідомлення від всіх дітей, він закінчує
5. Корінь (вузол, який запустив хвилю) закінчується, коли отримує повідомлення від всіх дітей

### Файли, які були модифіковані/створені

1. **`scheduler/core/lamport_clock.py`** (НОВИЙ)
   - Реалізація логічного годинника Лемпорта

2. **`scheduler/core/vector_clock.py`** (НОВИЙ)
   - Реалізація векторного годинника

3. **`scheduler/implementation/tarry_node.py`** (МОДИФІКОВАНИЙ)

   - Додано вивід значень годинників для відлагодження

4. **`scheduler/implementation/current_network.py`** (МОДИФІКОВАНИЙ)
   - Передача всіх ID вузлів до конструктора TarryNode

### Теоретична Основа

#### Логічний Годинник Лемпорта
- Забезпечує часткове впорядкування подій: якщо подія A "сталася раніше" ніж подія B, то `LC(A) < LC(B)`
- Не забезпечує сильне впорядкування (дві різні події можуть мати однакову часову мітку)
- Простіший і менш затратний у памяті

#### Векторний Годинник
- Забезпечує як часткове, так і сильне впорядкування
- Можна визначити причинно-наслідкові відносини між подіями
- Дозволяє визначити, чи були дві події паралельними або причинно пов'язаними
- Вимагає більше памяті (O(n) для кожного вузла, де n - кількість вузлів)

### Висновок

Реалізація успішно поєднує два методи логічного часу з алгоритмом Террі, дозволяючи системі відстежувати порядок подій у розподіленій мережі. Це корисно для отримання послідовних вивалів, відлагодження та аналізу поведінки розподіленої системи.
