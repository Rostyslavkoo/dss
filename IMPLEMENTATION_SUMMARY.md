# РЕЗЮМЕ РЕАЛІЗАЦІЇ ЛОГІЧНИХ ГОДИННИКІВ У АЛГОРИТМІ ТЕРРІ

## Задача
Реалізувати логічний годинник Лемпорта та векторний годинник на основі алгоритму Террі (tarry) у розподіленій системі.

## Виконана Робота

### 1. Створені Файли

#### `scheduler/core/lamport_clock.py`
Реалізація логічного годинника Лемпорта. Клас `LamportClock`:
- **`__init__(node_id)`** - ініціалізація з часовою міткою 0
- **`increment()`** - збільшує часовику мітку на 1 при локальній дії
- **`update_on_receive(received_timestamp)`** - оновлює часовику мітку при отриманні повідомлення за формулою: `max(local_timestamp, received_timestamp) + 1`
- **`get_timestamp()`** - повертає поточну часову мітку

**Теорія:**
- Забезпечує часткове впорядкування подій у розподіленій системі
- Якщо подія A "сталася раніше" ніж B, то `LC(A) < LC(B)`
- Простий механізм для відстеження причинно-наслідкових відносин

#### `scheduler/core/vector_clock.py`
Реалізація векторного годинника. Клас `VectorClock`:
- **`__init__(node_id, all_node_ids)`** - ініціалізація вектора для n вузлів з нулями
- **`increment()`** - збільшує локальний елемент вектора при локальній дії
- **`update_on_receive(received_vector)`** - оновлює вектор:
  - Для кожного j ≠ i: `vector[j] = max(local[j], received[j])`
  - Потім інкрементує локальний елемент: `vector[i] += 1`
- **`get_vector()`** - повертає копію поточного вектора

**Теорія:**
- Розширює концепцію логічного часу
- Дозволяє визначити, чи були дві eventi паралельними або причинно пов'язаними
- Забезпечує одночасно часткове і сильне впорядкування

## Висновок

Успішно реалізовано дві найважливіші системи логічного часу для розподілених систем в контексті алгоритму хвилі Террі. Реалізація дозволяє:

1. **Відстежувати причинно-наслідкові відносини** між подіями в розподіленій мережі
2. **Визначати паралельні события** (якщо вони існують)
3. **Забезпечувати послідовність** обробки даних
4. **Відлаговувати розподілені системи** з допомогою часових міток

Обидва типи годинників мають свої переваги:
- **Lamport Clock** - простіша, менше памяті, достаточно для багатьох задач
- **Vector Clock** - потужніша, дозволяє визначити більше відносин, але вимагає більше памяті

Реалізація підтримується розширюваною архітектурою системи та легко інтегрується з існуючим кодом.
